# 연구 잠금 상태에 따른 건설 단축키 순서 불일치

## 1. 개요
- **구분**: 사용성 개선 (Feedback / Improvement)
- **상태**: 분석 완료 및 개선 대기 (Open)
- **관련 시스템**: `ConstructionModeUI`, `BuildingUnlockElement`

---

## 2. 현상 및 문제점
- 건설 모드에서는 화면에 표시된 건물 버튼을 숫자 키 `1`, `2`, `3` 등으로 선택할 수 있습니다.
- 모든 관련 건물이 해금된 상태에서는 건물의 고정 순서에 따라 다음과 같이 동작합니다.
  - `1`: 벨트
  - `2`: 분배기
  - `3`: 병합기
  - `4`: 채굴기
- 그러나 연구 전에는 건설 UI에 `벨트`, `채굴기`, `제작기` 순서로 버튼이 표시되지만 다음과 같이 동작합니다.
  - `1`: 벨트 선택
  - `2`, `3`: 반응 없음
  - `4`: 채굴기 선택
- 화면에서 보이는 버튼 순서와 실제 숫자 단축키 순서가 달라 사용자가 현재 단축키를 직관적으로 예측하기 어렵습니다.

---

## 3. 원인 분석
- [`ConstructionModeUI.cs`](../../Assets/UI/Modes/Construction/ConstructionModeUI.cs)의 `HandleBuildingHotkeys()`는 연구 잠금 여부와 관계없이 전체 건물의 고정 순번으로 숫자 키를 처리합니다.
- 연구로 잠긴 건물 버튼은 `RefreshBuildingUnlocks()`에서 숨겨지지만 해당 번호는 이후 보이는 건물에 다시 할당되지 않습니다.
- 따라서 숨겨진 `분배기`, `병합기`가 각각 `2`, `3` 자리를 계속 차지하고, 화면상 두 번째 버튼인 `채굴기`는 기존 고정 번호인 `4`로만 선택됩니다.

---

## 4. 요구사항 (피드백 내용)
- 건설 모드의 숫자 단축키와 현재 화면에 표시된 건물 버튼의 순서를 일치시킵니다.
- 연구 전처럼 일부 건물이 잠긴 경우에는 숨겨진 건물을 제외하고 보이는 버튼에 `1`부터 연속된 단축키를 부여합니다.
- 예를 들어 화면에 `벨트`, `채굴기`, `제작기`만 표시된다면 다음과 같이 동작해야 합니다.
  - `1`: 벨트
  - `2`: 채굴기
  - `3`: 제작기
- 연구 완료로 버튼 목록이 변경되면 현재 표시 순서에 맞춰 단축키도 함께 갱신되어야 합니다.

---

## 5. 완료 조건
1. 숫자 키 `1`부터 화면에 표시된 건물 버튼 순서대로 건물이 선택됩니다.
2. 잠긴 건물 때문에 단축키 번호 사이에 반응하지 않는 빈 번호가 생기지 않습니다.
3. 버튼이 새로 해금되거나 잠금 상태가 변경된 뒤에도 표시 순서와 단축키 순서가 일치합니다.
4. 마우스로 버튼을 클릭했을 때와 숫자 단축키를 눌렀을 때 동일한 건물이 선택됩니다.
