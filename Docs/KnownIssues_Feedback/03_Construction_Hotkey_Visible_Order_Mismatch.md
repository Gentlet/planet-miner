# 연구 잠금 상태에 따른 건설 단축키 순서 불일치

## 1. 개요

- **구분**: 사용성 개선 (Feedback / Improvement)
- **상태**: 구현 완료 (Resolved)
- **관련 시스템**: `ConstructionModeUI`, `BuildingUnlockElement`

---

## 2. 현상 및 문제점

- 연구로 일부 건물이 잠기면 화면에서는 해당 버튼이 숨겨졌지만 숫자 단축키의 고정 번호는 그대로 남았습니다.
- 연구 전 `벨트`, `채굴기`, `제작기`만 보이는 경우에도 각각 `1`, `4`, `5`를 사용해야 했고 `2`, `3`은 반응하지 않았습니다.

---

## 3. 요구사항

- 숫자 키와 현재 화면에 표시된 건물 버튼 순서를 일치시킵니다.
- 숨겨진 건물을 제외하고 보이는 버튼에 `1`부터 연속된 단축키를 배정합니다.
- 연구 완료 등으로 표시 목록이 바뀌면 같은 프레임부터 새 표시 순서를 사용합니다.
- 마우스 클릭과 숫자 단축키가 동일한 건물 선택 동작을 호출해야 합니다.

---

## 4. 구현 결과

- UXML 표시 순서와 같은 건물 타입·버튼·선택 action 배열을 구성했습니다.
- `RefreshBuildingUnlocks()`가 각 버튼의 표시 여부와 단축키 계산용 상태를 함께 갱신합니다.
- 숫자 키 입력은 고정 건물 타입을 직접 호출하지 않고, 잠긴 버튼을 건너뛴 N번째 표시 버튼의 기존 클릭 action을 실행합니다.
- `1`부터 `9`까지는 첫 번째부터 아홉 번째 표시 버튼, `0`은 열 번째 표시 버튼에 대응합니다.
- 따라서 `벨트`, `채굴기`, `제작기`만 보이면 각각 `1`, `2`, `3`으로 선택됩니다.

---
