# 연구건물 명세

## 1. 문서 목적

이 문서는 연구건물과 전역 연구 시스템의 합의된 게임 규칙을 정의한다.

- 이 문서의 **확정 규칙**은 구현 기준으로 사용한다.
- 연구명, 연구 보상 구성, 비용과 시간 등 **임시 데이터**는 구조 검증용이며 이후 자유롭게 변경할 수 있다.
- 현재 런타임 구조를 판단할 때는 실제 코드와 `AGENTS.md`, 관련 `Docs/CodeMemory/` 문서를 최종 기준으로 삼는다.

## 2. 핵심 개념

- 한 시점에 전역 활성 연구는 하나만 존재한다.
- 모든 연구건물은 전역 활성 연구에 병렬로 기여한다.
- 연구건물을 많이 건설할수록 연구 완료 속도가 빨라진다.
- 연구 하나는 건물 해금, 제작 레시피 해금, 영구 성능 향상을 자유롭게 조합한 여러 보상을 가질 수 있다.
- 연구 상태와 완료 여부는 개별 연구건물이 아닌 전역 ECS 상태가 소유한다.
- 개별 연구건물은 입력 재료, 현재 1회분의 로컬 진행도, 전력 상태만 소유한다.

## 3. 연구건물 기본 사양

### 3.1 배치와 건설

- `BuildingTypeEnum`에 연구건물 타입을 추가한다.
- footprint는 `3×3`이다.
- 정사각 footprint이므로 회전해도 점유 크기는 변하지 않는다. 방향은 외형 회전에만 사용한다.
- 연구 시스템을 시작하는 기본 건물이므로 새 게임에서 처음부터 건설할 수 있다.
- 일반 건물과 동일한 배치, 셀 예약, 공사, 공사 취소, 철거, 파괴 수명주기를 사용한다.
- 임시 건설 비용은 철 3개와 구리 3개다. 이 수치는 전체 건물 밸런스 조정 시 변경한다.

### 3.2 전력

- 연구건물은 `PowerConsumer`다.
- 실제 최대 소비 전력은 설정 데이터로 관리하며 초기 구현 수치는 임시값으로 둔다.
- 전력 공급률에 비례하여 연구 속도가 감소한다.
- 전력 공급률이 0이면 진행 중인 연구 주기는 중단 지점에서 일시 정지한다.
- 전력이 복구되면 보존된 로컬 진행도부터 재개한다.

### 3.3 재료 투입과 보관

- 연구 재료는 벨트로만 자동 투입한다.
- 드론을 이용한 자동 공급이나 플레이어의 수동 공급 요청은 지원하지 않는다.
- 기존 제작기 입력 규칙처럼 footprint 전체에서 아이템을 수집한다.
- 현재 활성 연구의 1회분 재료에 포함된 아이템만 입력받는다.
- 전역 활성 연구가 없으면 어떤 재료도 입력받지 않는다.
- 각 재료의 최대 보관량은 해당 연구의 `1회 필요량 × 2`다.
- 연구건물에는 생산품과 아이템 출력 기능이 없다.
- 연구 변경으로 새 연구에 필요하지 않게 된 보관 아이템은 삭제하지 않는다. 기존 제작기의 부적합 재료 처리와 같은 소유권 경계를 사용해 드론 회수 대상으로 전환한다.

## 4. 연구 주기

### 4.1 시작 조건

연구건물은 다음 조건을 모두 만족할 때 1회 연구 주기를 시작한다.

1. 전역 활성 연구가 있다.
2. 활성 연구가 아직 완료되지 않았다.
3. 1회분에 필요한 모든 재료가 내부에 있다.
4. 전력 공급률이 0보다 크다.

주기를 시작할 때 1회분 재료 묶음을 원자적으로 모두 소비한다. 일부 재료만 먼저 소비하지 않는다.

### 4.2 진행과 완료

- 로컬 주기 진행 시간은 연구 정의의 `cycleDuration`을 사용한다.
- 실제 진행 시간에는 현재 전력 공급률을 반영한다.
- 로컬 주기가 끝나면 연구 정의의 `progressPerCycle`만큼 전역 확정 진척도를 올린다.
- 전역 진척도가 `requiredProgress` 이상이면 연구를 즉시 완료한다.
- 연구 완료 보상은 한 번만 적용한다.
- 완료 후 전역 활성 연구는 비운다. 다음 연구는 플레이어가 직접 선택한다.

### 4.3 여러 연구건물의 동시 진행

- 모든 연구건물은 별도의 로컬 주기를 동시에 진행할 수 있다.
- 남은 진척도에 대한 사전 예약이나 작업 수 제한은 두지 않는다.
- 한 건물의 완료로 전역 연구가 완료되면 다른 건물에서 진행 중이던 동일 연구의 로컬 주기는 즉시 삭제하고 0으로 초기화한다.
- 삭제된 주기를 시작하면서 이미 소비한 재료는 반환하지 않는다.
- 아직 주기를 시작하지 않아 내부에 보관 중인 재료는 유지한다.
- 완료 직전 병렬 진행으로 생기는 로컬 진행도와 소비 재료 손실은 다수 연구건물의 속도 이득에 따르는 의도된 비용이다.

## 5. 전역 연구 선택과 변경

- 연구건물이 하나도 없어도 전역 연구 패널을 열고 연구를 선택하거나 변경할 수 있다.
- 연구건물이 없으면 활성 연구는 유지되지만 진척도는 증가하지 않는다.
- 새 연구건물을 완성하면 현재 활성 연구에 자동으로 참여한다.
- 활성 연구는 완료 전에도 언제든 다른 연구로 변경할 수 있다.
- 연구 변경 확인창은 표시하지 않고 즉시 변경한다.
- 변경 전 연구의 전역 확정 진척도는 연구별로 보존한다.
- 변경 시 모든 연구건물의 진행 중 로컬 주기는 삭제하고 0으로 초기화한다.
- 삭제된 주기에서 이미 소비한 재료는 반환하지 않는다.
- 나중에 같은 연구를 다시 선택하면 보존된 전역 확정 진척도부터 이어서 진행한다.
- 완료된 연구는 다시 선택할 수 없다.

## 6. 선행 연구

- 연구는 0개 이상의 선행 연구를 가질 수 있다.
- 지정된 선행 연구를 모두 완료해야 해당 연구를 선택할 수 있다.
- 하나라도 완료하지 않았다면 연구 노드는 잠금 상태이며 선택할 수 없다.
- 선행 연구 관계는 임의의 깊이와 여러 갈래를 지원한다.
- 순환 선행 관계는 유효하지 않은 설정으로 처리한다.

## 7. 연구 보상

### 7.1 보상 목록

한 연구는 `rewards` 목록에 다음 보상을 여러 개 조합할 수 있다.

- `BuildingUnlock`: 지정 건물을 건설 가능 상태로 만든다.
- `RecipeUnlock`: 지정 제작 레시피를 선택 가능 상태로 만든다.
- `StatModifier`: 지정 대상의 영구 능력치 보너스를 추가한다.

기존 보상 종류만 사용하는 새 연구는 설정 데이터 추가만으로 만들 수 있어야 한다. 새로운 보상 종류를 추가할 때만 해당 보상을 실행하는 코드를 추가한다.

### 7.2 해금 표시

- 잠긴 건물은 건설 UI에서 숨긴다.
- 잠긴 제작 레시피는 제작기 UI에서 숨긴다.
- 연구 완료로 해금되는 즉시 해당 UI에 표시한다.
- 해금은 영구적이며 취소하거나 비활성화할 수 없다.

### 7.3 영구 성능 향상

- 성능 향상은 연구 완료 시점에 존재하는 건물과 이후 생성되는 건물에 모두 적용한다.
- 같은 능력치에 적용되는 퍼센트 보너스는 합산한다.
- 최종값은 `기본값 × (1 + 완료 연구 보너스 합계)`로 계산한다.
- 예를 들어 +10%와 +20%를 완료하면 최종값은 기본값의 1.3배다.
- `StatModifier`는 코드에서 명시적으로 지원하는 능력치 키만 사용할 수 있다.
- 임의 필드명, 리플렉션 또는 범용 메모리 접근으로 능력치를 변경하지 않는다.
- 최초 지원 능력치 목록은 실제 성능 향상 연구 콘텐츠를 정할 때 확정한다.

## 8. 데이터 정의

### 8.1 연구 식별자

- 각 연구는 변경되지 않는 고유 문자열 `stableId`를 가진다.
- 연구명, 설명, 표시 위치가 바뀌어도 `stableId`는 유지한다.
- 선행 연구, 전역 진척도, 완료 상태는 연구명이 아니라 `stableId`를 참조한다.
- 연구별 enum 항목을 추가하는 방식은 사용하지 않는다.

### 8.2 연구 정의 필드

각 연구 정의는 최소한 다음 데이터를 가진다.

- `stableId`
- 표시 이름과 설명
- `prerequisiteIds`
- `ingredients`: 1회분 재료 목록
- `cycleDuration`
- `progressPerCycle`
- `requiredProgress`
- `rewards`
- 테크 트리 표시용 행, 열 또는 이에 준하는 명시적 위치 값
- 동일 위치에서의 표시 순서

연구 정의는 별도 설정 파일에서 로드하여 ECS 설정 데이터로 게시한다. 정확한 파일명과 직렬화 형태는 구현 시 기존 `Resources/Config` 로더 관례에 맞춘다.

### 8.3 설정 검증

다음 조건은 설정 오류로 검출한다.

- 중복되거나 비어 있는 `stableId`
- 존재하지 않는 선행 연구 ID
- 자기 자신을 선행 연구로 참조하는 항목
- 순환 선행 관계
- 비어 있거나 잘못된 재료 타입, 0 이하의 재료 수량
- 0 이하의 주기 시간, 1회 진척도 또는 총 진척도
- 존재하지 않는 건물, 레시피 또는 능력치 보상 대상
- 지원하지 않는 보상 종류 또는 능력치 키
- 같은 대상을 모순되게 정의하는 중복 해금 보상

유효하지 않은 연구 정의를 일부만 조용히 적용하지 않는다. 오류를 명확히 보고하고 연구 설정 게시를 실패시켜 잘못된 해금 상태로 게임이 진행되는 것을 막는다.

## 9. UI 명세

### 9.1 전역 연구 패널

- 연구 선택은 개별 건물 UI가 아니라 전역 연구 패널에서만 수행한다.
- 설정 데이터의 위치 값을 사용하는 노드형 테크 트리로 표시한다.
- 잠긴 연구 노드도 표시하되 선택할 수 없게 한다.
- 잠긴 노드는 필요한 선행 연구를 표시한다.
- 선택 가능한 연구는 잠긴 연구와 구분되게 강조한다.
- 현재 활성 연구는 현재 선택 상태와 전역 진척도를 표시한다.
- 완료된 연구는 사라지지 않고 완료 상태로 계속 표시한다.
- 연구건물이 없으면 작동 가능한 연구건물이 0개임을 표시한다.
- 연구 변경에 따른 재료 손실 확인창은 표시하지 않는다.

### 9.2 개별 연구건물 UI

개별 연구건물 상세 UI는 상태 표시만 담당하며 전역 연구를 선택하지 않는다.

- 현재 전역 활성 연구 이름
- 연구건물의 로컬 1회분 진행도
- 다음 주기에 필요한 재료와 현재 보관량
- 불필요해져 회수 대기 중인 보관 재료
- 현재 전력 공급률과 유효 연구 속도
- 현재 작동 상태

최소 작동 상태는 다음을 구분한다.

- 활성 연구 없음
- 재료 대기
- 전력 없음
- 연구 진행 중
- 전력 부족으로 감속 중
- 다른 연구건물의 완료 또는 연구 변경으로 로컬 주기 초기화

마지막 초기화 상태는 영구 상태가 아니라 UI가 이해할 수 있는 짧은 결과 표시로 취급하며, 별도 게임플레이 소유자를 만들지 않는다.

## 10. 초기 콘텐츠 임시안

아래 연구명, 선행 관계와 보상 묶음은 구조 확인을 위한 임시 데이터다. 설정 변경만으로 교체하거나 확장할 수 있어야 한다.

### 10.1 처음부터 해금된 콘텐츠

- 건물: 벨트, 채굴기, 제작기, 창고, 전신주, 연구건물
- 제작 레시피: 철, 구리
- 메인스테이션은 기존 전용 부트스트랩 규칙을 유지한다.

### 10.2 임시 연구 노드

1. **물류 분배**
   - 선행 연구 없음
   - 분배기와 병합기 해금
2. **소재 가공**
   - 선행 연구 없음
   - 철봉과 구리봉 제작 레시피 해금
3. **석탄 발전**
   - 선행 연구: 소재 가공
   - 석탄 발전기 해금
4. **드론 물류**
   - 선행 연구: 물류 분배, 소재 가공
   - 드론 정거장과 드론 제작 레시피 해금

각 연구의 재료, 주기 시간, 1회 진척도, 총 진척도와 정확한 UI 위치는 임시 밸런스값으로 둔다.

## 11. 수명주기와 소유권 경계

- 전역 연구 선택, 진척도, 완료 목록과 해금 상태는 ECS 전역 상태가 소유한다.
- UI는 ECS 상태를 표시하고 연구 선택 변경 요청만 만든다. 별도 연구 상태 캐시를 소유하지 않는다.
- 연구건물의 아이템 저장, 소비, 복원은 기존 `ItemStorageSystem` 소유권 API를 사용한다.
- 연구건물 파괴 시 아직 소비하지 않은 내부 아이템은 기존 건물 파괴 규칙으로 월드에 복원한다.
- 이미 시작한 로컬 주기에 소비된 재료와 로컬 진행도는 연구건물 파괴 시 반환하지 않는다.
- 건설 재료 반환, 셀 점유 해제, 철거 작업과 회수 작업은 기존 `BuildingDestroySystem` 및 드론 수명주기를 따른다.
- 전력 연결과 공급률은 기존 `PowerGridSystem`의 참가자 규칙을 따른다.
- 구조 변경은 기존 ECB 재생 시점과 버퍼 무효화 규칙을 지킨다.

## 12. 완료 조건

구현은 최소한 다음을 만족해야 명세를 충족한다.

1. 연구건물을 기존 공사 수명주기로 건설하고 철거할 수 있다.
2. 여러 연구건물이 하나의 전역 연구를 실제로 병렬 진행한다.
3. 전체 재료 묶음만 원자적으로 소비하며 부분 소비가 발생하지 않는다.
4. 전력 비율에 따라 속도가 변하고 0 전력에서 진행도가 보존된다.
5. 연구 변경 시 전역 확정 진척도는 보존되고 모든 로컬 주기는 즉시 초기화된다.
6. 연구 완료 시 보상이 정확히 한 번 적용되고 다른 로컬 주기가 정리된다.
7. 건물 및 레시피 해금이 숨김 상태 UI에 즉시 반영된다.
8. 선행 연구 조건과 노드 표시 상태가 설정 데이터와 일치한다.
9. 기존 및 신규 건물에 영구 성능 향상 계산이 일관되게 적용된다.
10. 연구 정의 추가와 기존 연구명, 선행 관계, 보상 조합 변경이 기존 보상 종류 범위에서는 코드 수정 없이 가능하다.
11. 잘못된 연구 설정은 조용히 부분 적용되지 않고 명확한 로드 실패로 보고된다.
